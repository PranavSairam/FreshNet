------------------------------------------------------------------------------
1. WHAT FRESHNET IS
------------------------------------------------------------------------------
FreshNet looks at ONE photo of a fruit or vegetable and answers with one of two
labels:

    Fresh   (class index 0)
    Spoiled (class index 1)

It is a local, academic monorepo containing:
  - a data pipeline (dataset preparation, integrity audit, split building)
  - a training and evaluation pipeline (PyTorch)
  - a deployment exporter (versioned weights bundle)
  - an HTTP API (FastAPI) that loads the exported model once at startup
  - a website (React + Vite + Tailwind) with an upload-and-analyze page

The answer is a VISUAL ESTIMATE ONLY. It is not a food-safety check, a shelf-life
estimate, or a freshness percentage (see section 13).

There is NO "Medium" class. Medium freshness is a possible future extension and
is not implemented or claimed anywhere.


------------------------------------------------------------------------------
2. THE MODEL IN ONE PARAGRAPH
------------------------------------------------------------------------------
The deployed model is "FusedFreshNet". It reads each photo two ways at once:
  - a CONTEXT branch (EfficientNet-B0) looks at the whole picture at 224x224
  - a DETAIL branch (a small CNN trained from scratch) looks at five close-up
    160x160 patches (four corners + centre) cut from a 384x384 version
The two summaries (256 numbers each) are joined, normalised, and turned into
two scores (logits): one for Fresh, one for Spoiled. The larger score is the
label (argmax). There is no tuned threshold.


------------------------------------------------------------------------------
3. ARCHITECTURE DETAIL
------------------------------------------------------------------------------
Context branch
  - torchvision EfficientNet-B0
  - Initialised from ImageNet weights at TRAINING time. The trained weights are
    stored inside the exported state_dict, so inference builds the network with
    pretrained=False and never downloads anything.
  - Input: whole image resized to 224x224 (taken from the 384x384 image)
  - Output: 256-dimensional embedding

Detail branch
  - Small convolutional network trained from scratch (no pretrained weights)
  - Input: five 160x160 patches (four corners, then centre) from the 384x384
    image
  - Each patch gets an embedding; the five embeddings are averaged, then a
    Linear + ReLU gives a 256-dimensional embedding

Fusion head
  - Concatenate 256 + 256 = 512 numbers
  - LayerNorm -> Dropout(0.3) -> Linear -> 2 logits [Fresh, Spoiled]

Decision rule
  - argmax over the two logits
  - Softmax over the class dimension is used ONLY to show probabilities on the
    website. The label never depends on a threshold.

Why two branches: the context branch sees overall colour/shape; the detail
branch focuses on local texture such as mould, bruises, and wrinkling.


------------------------------------------------------------------------------
4. INPUT PREPROCESSING (FROZEN - TRAINING EVAL AND DEPLOYMENT SHARE ONE PATH)
------------------------------------------------------------------------------
  1. Open image with PIL, convert to RGB (no EXIF auto-rotation applied)
  2. Resize to 384x384 (bilinear, antialiased) - this squares the image; it
     does not crop or preserve aspect ratio
  3. Context view: resize that 384x384 image to 224x224 (bilinear)
  4. Detail patches: five 160x160 crops from the 384x384 image
       - four corners, then the centre
       - as shares of the square: corners at 0% and 58.33%, centre at 29.17%,
         each patch 41.67% wide/tall
  5. ToTensor, then ImageNet normalisation, once per branch input
       mean [0.485, 0.456, 0.406]   std [0.229, 0.224, 0.225]
  6. No augmentation at inference. Evaluation is deterministic.

Training-time augmentation (NOT used at inference): horizontal flip p=0.5,
rotation up to 12 degrees, light colour jitter (brightness/contrast 0.08,
saturation 0.05, hue 0.01).

The website draws the same five patch boxes over your uploaded photo so you can
see which regions the detail branch reads.


------------------------------------------------------------------------------
5. DATASET AND SPLITS
------------------------------------------------------------------------------
Task: binary visual classification, Fresh vs Spoiled, of fruit and vegetable
images.

Source collection: 71,318 images in the original dataset.
Benchmark used ("v3"): 53,052 images INCLUDED; 18,266 images QUARANTINED
(listed in exclusions.csv) because they could not be trusted for a clean
split. The quarantine and the manifests are in data/processed/manifests_v3_source/.

Split sizes (v3):
  train  37,164   Fresh 24,094   Spoiled 13,070
  val     7,853   Fresh  5,118   Spoiled  2,735
  test    8,035   Fresh  5,309   Spoiled  2,726

Split fingerprint (v3):
  4f2534505b3ca656e72b786046d0d7f7da1088a221fe857a3b16639bd87c8f57

Leakage handling and its limits (be honest about these):
  - Confirmed same-capture links (images of the same specimen/capture) were
    kept within one split: zero cross-split crossings among confirmed links.
  - The near-duplicate candidate search was CAPPED at 64 comparisons per image
    inside an average-hash band. It is NOT exhaustive.
  - Therefore FreshNet does NOT claim the benchmark is leakage-free.
  - Specimen-level metadata was not available, so leakage-free cannot be
    claimed.

The dataset itself (about 6.6 GB) is NOT in the git repository.


------------------------------------------------------------------------------
6. TRAINING
------------------------------------------------------------------------------
Hardware/software: Apple M5 (no CUDA), PyTorch 2.14.0, torchvision 0.29.0,
Python 3.12.15, float32 on MPS (mixed precision is CUDA-only and was not used).

Recipe (all three models, config: configs/train_v3.yaml):
  - Optimiser: AdamW, cosine learning-rate schedule
  - Backbone frozen for the first 3 epochs, then two learning rates:
      head 3e-4, backbone 3e-5
  - Batch size 16, seed 42, class weights to offset Fresh/Spoiled imbalance
  - Maximum 30 epochs, early stopping patience 7 on VALIDATION macro F1
  - Checkpoints saved at epoch end; best-by-validation kept

Three models were trained and compared:
  CONTEXT  (EfficientNet-B0 branch alone)   26 epochs, early-stopped, ~4.48 h
  DETAIL   (patch CNN alone)                30 epochs, ~2.81 h
  FUSED    (both branches joined)           30 epochs, ~6.21 h
Whole v3 run: about 18 h 20 min wall clock
  (2026-10-11T13:50:04Z to 2026-10-12T08:10:25Z).

An earlier "original split" run (fingerprint 005d7500...50f9) exists but is
HELD and is not used for any final result. It is kept for the record only and
its scores must never be compared with v3 as an "improvement" or "decline".

How to read this:

10. HTTP API (BACKEND)
------------------------------------------------------------------------------
Stack: FastAPI + Uvicorn, SQLite (local). Env prefix FRESHNET_.

Startup: loads the bundle ONCE (settings: FRESHNET_BUNDLE_DIR, FRESHNET_DEVICE,
default device cpu). Inference runs under a lock in a worker thread.

Endpoints
  GET  /api/health    API status, model status (available / ready|unavailable,
                      message, architecture, model_version), database status
                      (path reported only as "local-sqlite")
  POST /api/predict   multipart form field "file"; optional field "produce"
                      (a catalogue id such as banana, or unknown)
  GET  /api/produce   supported produce types for the selector
  GET  /api/guidance  ?produce=&freshness= -> label, severity and guidance
                      from the catalogue (the model is not run)
  GET  /docs          interactive API docs

Response of /api/predict includes: label, class index, probabilities for Fresh
and Spoiled, model_version, and elapsed_ms (decode + validation + preprocessing
+ model forward). It also carries combined_label (for example "Fresh banana",
or "Fresh produce" when identity is unknown), produce {id, label, source,
model_version, probabilities}, freshness {...}, severity (always
status "not_assessed") and guidance (reviewed, sourced, general advice).

Produce identity and guidance (added 2026-10-16)
  - Produce identity is SELECTED BY THE USER. FreshNet has no produce
    classifier and does not recognise produce from the photo. There is no
    unknown / non-produce detector.
  - The freshness model, preprocessing, argmax rule and weights are unchanged.
  - Spoilage severity is not assessed. The model only separates Fresh from
    Spoiled.
  - Guidance comes from a versioned catalogue built from FDA, USDA FSIS,
    UC Davis Postharvest and UC Master Gardener pages. Storage advice is
    reviewed for 11 produce types; bitter gourd is awaiting review.
  - Details: docs/PRODUCE_IDENTIFICATION_AND_GUIDANCE.md,
    docs/SEVERITY_PROPOSAL.md, docs/PRODUCE_LABEL_INVENTORY.md.

Example (real run, validation image, not a benchmark score):
  label Fresh, Fresh prob 0.99999988, Spoiled prob 7.6e-08,
  elapsed 104 ms on CPU.

Input policy (a bad upload is turned back with a reason, never silently
altered):
  - Formats: static JPEG or PNG only (checked by real image format, not by
    filename or MIME type)
  - Max 8 MB upload and 16,000,000 pixels (8,000 px on any edge)
  - Rejected: animated images, any transparency (RGBA/LA/palette with alpha),
    EXIF orientation other than normal, corrupt files, empty uploads
  - Errors are JSON {code, message}; no file paths or stack traces are exposed

If the model bundle is missing, health still reports the API as up but the model
as unavailable, and predictions return 503. There is no mock model.

11. WEBSITE (FRONTEND)
------------------------------------------------------------------------------
Stack: React 19, Vite 8, Tailwind 4, TypeScript. Single page. Dev server on
port 5173, proxying /api to the backend on port 8000.

Sections (exact names): Home, Analyze, How It Works, Model Performance,
About / Team.

Design (latest redesign)
  - Flat sand and moss-green palette, light geometric type (Stack Sans)
  - Hero with a masked two-line headline and the working analyzer beside it
  - Animated drawn fruits and vegetables (apple, tomato, lemon, carrot,
    broccoli, banana) in Fresh and Spoiled states; the belt lets you press a
    drawing to flip it. These are ILLUSTRATIONS, not model output.
  - The analyzer draws the five detail patches over your photo
  - A pinned "How it reads a photo" stage that changes as you scroll
  - Model Performance with recorded numbers and animated bars
  - Four real credited pictures from open collections (photographs and a 1901
    seed-catalogue plate); credits are in the footer
  - Respects prefers-reduced-motion and keyboard focus

A "Produce type" selector appears once a photo is chosen ("Selected by you").
Result card shows: "Predicted: Fresh banana" (or "Fresh produce" when unknown),
who set the produce identity, the model's Fresh/Spoiled label and both
probabilities, the statement that they are model outputs and not a freshness
percentage, model version, elapsed time, "Spoilage severity: Not assessed",
and below it compact guidance (Suggested next steps, Storage guidance, What to
check yourself, a food-safety note and a sources list). Changing the photo
clears the result; changing the produce type updates only the label and advice.

13. WHAT FRESHNET DOES NOT CLAIM (IMPORTANT LIMITS)
------------------------------------------------------------------------------
  - It is NOT a food-safety tool. A Fresh label does not mean safe to eat.
  - It does NOT estimate shelf life, age, or a freshness percentage.
  - The displayed probabilities are the model's class scores after softmax.
    They are NOT calibrated confidence, and "100.0% Fresh" does not mean
    certainty.
  - It judges what is VISIBLE: colour, bruising, mould, texture. It cannot see
    smell, taste, internal rot, or storage history.
  - The benchmark may still contain near-duplicates (search was not
    exhaustive) and was not verified leakage-free. Scores may be optimistic
    compared with new real-world photos.
  - 18,266 of 71,318 images were quarantined and excluded; scores apply to the
    53,052-image benchmark only.
  - Spoiled-predicted-as-Fresh errors (86 of 2,726 on test) are the riskiest
    mistake type.
  - Results from the older original split are held and must not be compared
    with the v3 results.
  - Only two classes exist. Anything "in between" is forced into Fresh or
    Spoiled.
  - Generalisation to produce types, cameras, or lighting not represented in
    the dataset is untested.

14. HOW TO RUN IT LOCALLY (macOS)
------------------------------------------------------------------------------
Backend (from the project root):
  PYTHONPATH="$PWD/backend:$PWD/ml" backend/.venv/bin/python -m uvicorn \
      app.main:app --host 127.0.0.1 --port 8000

Frontend:
  cd frontend
  npm install          # first time only
  npm run dev -- --host 127.0.0.1 --port 5173

Then open http://127.0.0.1:5173/

Or start both with:  bash scripts/start_local.sh

Useful settings (backend/.env, which is git-ignored; see .env.example):
  FRESHNET_BUNDLE_DIR=artifacts/deployment/v3/fused_epoch29_b962c650ed80
  FRESHNET_DEVICE=cpu

Production build of the site:  cd frontend && npm run build
Tests:  backend/.venv/bin/python -m pytest tests

17. ONE-SENTENCE SUMMARY FOR A REPORT OR VIVA
------------------------------------------------------------------------------
FreshNet is a two-branch deep-learning classifier (EfficientNet-B0 on the whole
image plus a small CNN on five close-up patches, fused into a Fresh/Spoiled
decision) that scored 98.33% accuracy and 0.981 macro F1 on a held-out test set
of 8,035 images from a cleaned 53,052-image benchmark, selected using validation
data only, and served through a FastAPI backend and React website as a visual
estimate - not a food-safety check.
