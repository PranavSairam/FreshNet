# Produce label inventory

Generated by `ml/audit_produce_labels.py` from the v3 manifests
(`data/processed/manifests_v3_source/`). It reads metadata only. No image was
opened, no model was trained, and the freshness model was not touched.

The only produce-type signal in this repository is the **dataset folder name**
(for example `FreshBanana`, `RottenBanana`). There is no `specimen_id`,
no separately annotated produce-type column, and **no produce classifier or
checkpoint**. The deployed model predicts Fresh/Spoiled only.

## Findings

### Missing labels

Every included image has a folder-derived produce type. No row was missing one.
That is a folder-name label, not an independently verified annotation.

### Label conflicts and ambiguities

- **okra** appears under different folder spellings: Okara, Okra. Folder names must be normalised before training.
- **capsicum** appears under different folder spellings: Capciscum, Capsicum. Folder names must be normalised before training.
- `FreshBittergroud` / `RottenBittergroud` look like a misspelling of bitter gourd. The mapping to `bitter_gourd` is an assumption that needs human review.
- `Bellpepper` and `Capsicum` are separate folders, but a bell pepper is a capsicum. The two classes overlap and a classifier could not tell them apart reliably without a defined rule.
- Several produce types have few images (see the table). Okra (529), bitter gourd (680), strawberry (873), mango (1,060) and bell pepper (1,078) are small against tomato (11,431), carrot (10,434) and orange (10,337).
- Class balance differs by produce type (carrot, orange and tomato are mostly Fresh; apple, potato and strawberry lean Spoiled), so a produce classifier could pick up freshness cues instead of produce identity.
- **A source group contains two different produce types** and needs human review (a near-duplicate false match, or a misfiled image): RottenBellpepper (train): Rotten/RottenBellpepper/rottenPepper (488).jpg; RottenCarrot (train): Rotten/RottenCarrot/rottenCarrot (65).jpg. Both rows are in the same split, so no split boundary is crossed.

### Checks that passed

- Every Fresh*/Rotten* folder agrees with its Fresh/Spoiled label.
- No identical image appears under two different produce types.
- No source group crosses train, validation and test.

### Limits of this audit

- Folder names are the only evidence. Wrongly filed images would not be found.
- The dataset has no specimen metadata, and the near-duplicate search was not
  exhaustive (see `docs/TRAINING.md`). Leakage-free cannot be claimed.
- Many images are augmented copies (rotated, translated). Counts are images,
  not distinct specimens.
- The data has no non-produce or out-of-scope images, so an Unknown/non-produce
  detector cannot be trained or evaluated from it.
